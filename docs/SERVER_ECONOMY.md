# Серверный баланс — контракт этапа

Релиз: 25 октября 2026 года. Миграция `server_wallet` применена в рабочем проекте (версия БД `20261025105819`); `server-wallet` v1 и обновлённые `server-durak`/`server-poker` v2 имеют статус ACTIVE, JWT обязателен. Интерфейс входит в этот релиз. Настоящий вход владельца и перенос телефон → ПК ещё не проверены.

## Граница доверия и совместимость

Существующий профиль, баланс практики и пять обычных партий сохраняются без изменений. Они не становятся проверенными сервером автоматически. Новый серверный баланс хранится отдельно в `vezdehot_private`, не входит в облачный checkpoint, не импортируется из гостя и не меняется через `updateProfile`/`recordResult`.

В интерфейсе используются названия «Баланс практики» и «Серверный баланс». Это игровые монеты без денежной стоимости. Серверные столы предлагают прежнюю бесплатную практику (по умолчанию) или вход за 100 V. Существующая партия без поля `economy` остаётся бесплатной.

## Правила

- Один стартовый грант 1 000 V на подтверждённый аккаунт. Он создаётся лениво при первом чтении серверного кошелька; старые монеты не конвертируются.
- Бонус 1 000 V раз в 24 часа по времени БД. Первый бонус доступен через 24 часа после стартового гранта.
- Дурак: вход 0 или 100 V один раз на партию. В платной партии победа возвращает `100 × число игроков`, ничья 100, поражение/выход 0. За завершённую по правилам платную партию XP: победа 80, ничья 40, поражение 25; за сдачу 0. Бесплатная партия не меняет кошелёк/статистику.
- Покер: вход 0 или 100 V один раз на весь стол, 1 000 стартовых фишек. Новая раздача не списывает монеты. Платный стол можно закрыть только после завершённой раздачи; при проигрыше всех фишек или победе над всеми ботами закрывается автоматически. Возврат `floor(текущие фишки игрока / 10)`, а не устаревшее поле payout предыдущей раздачи. XP 90/40/20 при возврате больше/равном/меньшем 100 V. Бесплатные столы сохраняют прежнее поведение выхода и не меняют кошелёк.
- Число платных партий увеличивается один раз на окончательный расчёт стола; wins только при положительном исходе. Покер считается победой при возврате >100 V. Сдача в Дураке считается проигранной партией без XP.

## Публичные контракты

Новый `server-wallet` Edge Function проверяет bearer через Auth `/user` как существующие серверные игры. Клиент не передаёт UID, сумму, XP или время. Разрешены только `{op:'load'}` и `{op:'claimDaily',actionId:UUID}`. CORS — прежние два production-origin; JWT обязателен.

`load` возвращает `{status:'ok',wallet}`. `claimDaily` возвращает квитанцию `{status:'saved'|'cooldown',actionId,availableAt?}`. Клиент хранит точное тело до подтверждения, затем читает свежий кошелёк. Ответ бонуса не устанавливает старый баланс поверх свежего.

`wallet` = `{version:1,revision,balance,xp,games,wins,bonusAvailableAt,serverTime,history}`. Даты — ISO UTC; история до 20 последних записей `{id,kind,game,tableId,delta,xp,balance,createdAt}`. `kind`: `welcome`, `daily`, `entry`, `settlement`; game/tableId null для грантов. revision монотонна, безопасное целое.

`server-durak`/`server-poker` принимают в `start` дополнительное необязательное `stake:0|100`, по умолчанию 0. Внутренний state и публичная game projection содержат `economy:{version:1,stake,settled,payout,xp,outcome}`. До расчёта payout/xp=0,outcome=null; после — outcome `win|draw|loss|resigned`. Отсутствующее economy у старой партии означает бесплатную практику. Движок фиксирует economy до commit, клиент не задаёт результат.

Клиент читает кошелёк отдельным модулем; игровые ответы не обязаны содержать wallet. После любого подтверждённого изменения стола модуль перечитывает свежий кошелёк. Пока он недоступен, показывается неизвестный/необновлённый баланс; платный старт не предлагается как гарантированный. БД остаётся последним арбитром достаточности средств.

## Транзакции и права

- `server_wallet_read(p_user_id)` и `server_wallet_claim(p_user_id,p_action_id,p_request)` доступны только service_role; UID берётся из проверенного Auth user на Edge. Все таблицы закрыты от anon/authenticated, RLS включён.
- `server_wallets`, неизменяемый `server_wallet_ledger`, постоянные `server_wallet_receipts` находятся в `vezdehot_private`. Уникальные ключи entry/settlement включают пользователя, тип игры и стабильный ID стола. На таблицах ledger/receipts service_role не получает UPDATE/DELETE.
- Существующие `server_durak_commit`/`server_poker_commit` сохраняют прежние сигнатуры и CAS/квитанции. Входное списание или итоговое начисление совершается в той же транзакции, что state и квитанция игры. При недостатке средств возвращается SQLSTATE `P0001` с сообщением `insufficient_funds`; Edge переводит его в HTTP 422 error `insufficient_funds`. Ревизия/карты/баланс не изменяются.
- Обработка существующей квитанции идёт до новых денежных изменений. Списание/начисление невозможно повторить другим actionId для того же tableId. Старые Edge-клиенты без economy остаются совместимы как бесплатные.
- Клиентский checkpoint не имеет доступа к этим таблицам и функциям, не перезаписывает их. Операции разных игр и бонуса сериализуются блокировкой одного кошелька пользователя; порядок блокировок не создаёт взаимной блокировки.

## Приёмка

Изолированные SQL-проверки: права, стартовый грант один раз, бонус/часы БД/повтор UUID/другой запрос с тем же UUID, атомарное списание, недостаток средств, однократный результат, сохранение при откате, CAS разных устройств и общий баланс двух игр. Движок: сохранение economy между раздачами, запрет платного выхода посреди раздачи, корректный текущий cashout и все исходы Дурака. Клиент: потерянный ответ, неверное подтверждение, повтор после перезагрузки, смена аккаунта и отсутствие устаревшего баланса. Реальная проверка владельца на телефоне и ПК остаётся отдельным пунктом.

### Проверки релиза

- 399 автоматических тестов прошли: движки, Edge, клиенты, сохранения, владение вкладкой и интерфейс. Канонические ядра Дурака/Покера совпадают с генераторами.
- `scripts/test-server-wallet-sql.cjs`: новые SQL-проверки кошелька и прежние SQL-проверки обоих серверных режимов проходят в изолированном PGlite. Проверены роли, откаты, повтор квитанций, конкуренция за последние монеты и изоляция от фактического клиентского checkpoint. Это последовательная модель транзакций, а не нагрузочный тест параллельных подключений.
- `scripts/test-server-economy-integration.cjs`: настоящий клиент → Edge → движок → SQL в изолированной БД. Проверены потерянный ответ платного входа и перезапуск клиента, естественный результат Дурака, две раздачи Покера без второго входа и однократный расчёт.
- Браузерный стенд с реальными движками и тестовыми Auth/ledger: Дурак на ширине 320/390 и горизонтальных 844×390, повтор партии, выбор и защита карт; Покер — две раздачи, баланс 700 V до расчёта и 796 V после возврата 96 V; бонус с потерянным ответом начислен один раз. Это тестовые данные, не аккаунт владельца.
- Production: каждый из трёх Edge endpoint отвечает 401 без входа, CORS preflight — 204. После миграции нет новых предупреждений security advisor. Реальные данные игроков не использовались для этих проверок.
