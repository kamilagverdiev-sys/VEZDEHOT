# Серверный покер

Это отдельный тренировочный стол: четыре места, три бота, по 1000 фишек, блайнды 20/40. Бесплатная практика остаётся по умолчанию; необязательный вход за 100 V использует отдельный защищённый [серверный баланс](SERVER_ECONOMY.md). Обычный покер, его баланс практики и сохранение остаются самостоятельными. Расширение экономики реализовано и проверено; серверное развёртывание описано в [контракте кошелька](SERVER_ECONOMY.md).

## Правила и несколько раздач

Сервер выбирает колоду, проверяет очередь и размер ставки, играет за ботов и распределяет основной и побочные банки. Клиент передаёт только выбранное действие. Он не может задавать чужое место, карты, исход, стек или выплату.

`core.mjs` генерируется из `POKER_ENGINE_START` / `POKER_ENGINE_END` в `dist/poker.html` и публичного оценщика `dist/poker-equity.js`. Правила не переписаны вторым независимым движком. После изменения исходных правил выполнить `node scripts/sync-server-poker-core.cjs`; вариант `--check` проверяет точное совпадение. Генератор помещает оба исходника в отдельную фабрику и передаёт `crypto.getRandomValues` вместо `Math.random`, не изменяя глобальные объекты. Созданные движком технические идентификаторы заменяются UUID сервера до сохранения.

После завершения раздачи остаются те же стеки и тот же стол. «Следующая раздача» меняет дилера, пропускает выбывшие места и раздаёт новые карты. Для двух оставшихся игроков действуют правила heads-up: дилер ставит малый блайнд и ходит первым до флопа. Стол завершается после потери всех фишек игроком, победы над всеми ботами либо явного закрытия. Бесплатный стол разрешено закрыть посреди раздачи без выплаты. Стол за 100 V можно закрыть только после завершённой раздачи; прежний результат руки не разрешает выход во время следующей.

Каждый запрос исполняет не более двух ходов ботов. Следующая улица всегда открывается отдельным действием `continue`; оно также продолжает очередь ботов, если после лимита остался ход бота. Фоновая вкладка сама не двигает стол. Значение кнопки определяется текущей фазой: продолжить ходы соперников, открыть флоп/тёрн/ривер или показать вскрытие.

## Экономика

Старт принимает `stake: 0 | 100`; отсутствие поля и старое сохранение без `economy` означают бесплатную практику. Вход за 100 V списывается один раз на постоянный UUID стола, следующие раздачи не оплачиваются. При окончательном закрытии возвращается `floor(текущие фишки игрока / 10)` V; поле выплаты прошлой раздачи не используется. XP — 90/40/20, если возврат больше/равен/меньше 100 V. Игровая статистика учитывается один раз за стол; бесплатная практика не меняет кошелёк или статистику. Списание, расчёт, состояние и квитанция записываются одной транзакцией.

## Закрытые карты и вероятность

Колода, сожжённые карты и полные руки ботов хранятся в закрытой схеме и не передаются клиенту. Публичный ответ содержит руку человека, общие карты, открытые ставки и размеры стеков. Рука бота и название его комбинации раскрываются только на завершённом вскрытии, если бот не сбросил карты. Выигрыш без вскрытия не раскрывает руку победителя; сброшенные карты не раскрываются никогда.

Боты получают оценку только из собственной руки, общих карт и количества соперников. Оценщик строит независимый равномерный пул; он не получает настоящую колоду, сожжённые карты или чужие руки. Оценка шанса для игрока также использует только его руку и открытые карты. Процент — моделирование против равномерных неизвестных рук, не обещание выигрыша и не результат чтения карт соперников.

## API

`POST https://cyzbraifdkrqicdsbuwe.supabase.co/functions/v1/server-poker`

Нужны `Content-Type: application/json`, публичный `apikey` проекта и `Authorization: Bearer <access_token>` постоянного аккаунта. Встроенный серверный секрет не передаётся браузеру. Разрешены два production-origin VEZDEHOT; действуют отдельная проверка пользователя через Auth и запрет анонимных аккаунтов.

| Операция | Тело |
| --- | --- |
| Загрузить стол | `{ "op": "load" }` |
| Начать новый | `{ "op": "start", "actionId": "UUID", "expectedRevision": 0, "difficulty": "normal", "stake": 0 }` |
| Уравнять | `{ "op": "action", "actionId": "UUID", "expectedRevision": 1, "gameId": "TABLE_UUID", "action": { "type": "call" } }` |
| Повысить до 160 | Такой же конверт с `action: { "type": "raise", "amount": 160 }` |
| Продолжить | Такой же конверт с `action: { "type": "continue" }` |
| Следующая раздача | Такой же конверт с `action: { "type": "nextHand" }` |
| Закрыть стол | Такой же конверт с `action: { "type": "close" }` |

Поддерживаются сложности `easy`, `normal`, `hard`. Дополнительные действия — `fold`, `check`; `resign` является серверным синонимом `close`. Только `raise` принимает `amount`: это **общая ставка игрока на текущей улице**, а не добавляемое число фишек. Целое число меньше минимального повышения допустимо только при ставке всех оставшихся фишек. Дополнительные поля запрещены.

Ответ: `{status: "ok" | "saved" | "conflict", revision, game}`. `game` равен `null`, если стол ещё не создан. Ревизия монотонна на аккаунт, не сбрасывается при новой раздаче или новом столе. `game.economy` содержит `{version, stake, settled, payout, xp, outcome}`. При недостатке серверного баланса старт возвращает HTTP 422 `insufficient_funds`, не меняя игру или деньги.

`game.id` — постоянный UUID стола; `game.handId` меняется при новой раздаче. `game.handOver` означает завершение текущей раздачи. `game.over` означает завершение **всего стола**: после обычной выигранной раздачи это значение остаётся `false`. `legal.actions` перечисляет доступные сейчас действия, а `callAmount`, `owed`, `minimum`, `maximum` задают параметры текущего хода. Сервер заново проверяет выбор независимо от этих подсказок.

Публичная проекция также содержит `phase`, `stage`, `difficulty`, `handNumber`, `button`, `smallBlind`, `bigBlind`, `toAct`, `pot`, `paidPot`, `handProfit`, `community`, `players`, `showdown`, `prizes`, `pots`, `tableClosed`, `tableFinished`, `result`, `lastAction`, `history`, `tableHistory`. Комбинация имеет поля `{name, category, cards, parts}` и появляется только там, где разрешено показывать руку. При закрытии активной бесплатной раздачи `phase` равен `over`, `over` равен `true`, а `handOver` остаётся `false`. Для стола за 100 V такое действие запрещено.

## Сохранение и повтор запроса

Миграция `20261025094046_server_poker_actions.sql` создаёт закрытые таблицы состояния и квитанций Покера. Расширение `20261025110000_server_wallet.sql` связывает их commit с отдельным общим кошельком серверных Дурака и Покера; прежний checkpoint пяти обычных игр остаётся независимым. Только серверная роль может выполнять `server_poker_read` / `server_poker_commit`; браузерные роли не читают внутренние состояния даже при известном UUID аккаунта.

CAS, квитанция и денежное изменение записываются в одной транзакции. Повтор UUID стола не позволяет повторить входное списание или итоговую выплату. Одинаковые `actionId` и тело возвращают исходную квитанцию; тот же UUID с другим телом отклоняется. Два устройства не могут успешно записать разные действия поверх одной ревизии. Новый стол нельзя начать поверх активного: сначала его надо завершить или явно закрыть.

Клиент сохраняет точный запрос до отправки. При потерянном ответе повторяется тот же UUID с тем же телом. Квитанция может относиться к более ранней ревизии, поэтому после неё клиент заново запрашивает `load`, а не восстанавливает старое отображение. Смена аккаунта, потеря права вкладки, ошибки локального хранилища и повреждённый незавершённый запрос блокируют неподтверждённые действия. После подтверждения стол и кошелёк читаются отдельно: старая игровая квитанция не откатывает свежий баланс.

Базовая версия опубликована 25 октября 2026 года: миграция серверного Покера применена, Edge Function `server-poker` активна (версия 1, `verify_jwt: true`). В тот же день применена миграция кошелька `20261025105819`, `server-poker` обновлён до v2, новая `server-wallet` v1 ACTIVE; обе функции требуют JWT. Проверены метаданные прав: браузерные роли не вызывают RPC, сервисная роль имеет доступ. Запрос без входа отклоняется, обычный CORS preflight разрешён, публичный вызов закрытого RPC запрещён. Эти проверки не читают игровые данные аккаунтов и не заменяют приёмку настоящего входа.

## Проверки и ограничения

`node --test tests/server-poker-engine.cjs` проверяет сохранность всех 52 карт и 4000 фишек в 90 воспроизводимых столах на трёх сложностях, переходы между раздачами, завершение столов, права действий, ограничение работы ботов, закрытие стола без фиктивной выплаты, независимость ботов от скрытой информации, отсутствие утечек и отказ при повреждении внутреннего состояния. Генерация правил также проверяется на точное совпадение.

SQL-проверки запускаются только на изолированной базе, не на данных игроков. Тесты HTTP-обработчика и браузерный стенд используют тестовые сервисы; они не доказывают настоящий Google-вход или перенос сессии конкретного пользователя. Приёмка настоящего аккаунта между телефоном и ПК остаётся отдельным пунктом. Google OAuth требует настройки внешнего провайдера и ввода секрета непосредственно в Supabase.

`node scripts/test-server-wallet-sql.cjs /absolute/path/to/node_modules/@electric-sql/pglite` проверяет права, общий кошелёк двух игр, все выплаты, недостаток средств, повторы и откат транзакций. Изолированный интеграционный тест использует настоящие Edge-обработчики, движки и SQL: проверены несколько раздач за одним входом и окончательная выплата по текущим фишкам.

Далее — приёмка настоящих устройств и перенос остальных игр на сервер. Google остаётся выключен; Google Cloud в текущем облачном браузере возвращает `Site Unavailable`. Настоящий вход владельца и перенос телефон → ПК не проверены. Старые клиентские игры и их баланс практики не становятся защищёнными от добавления этого кошелька.
