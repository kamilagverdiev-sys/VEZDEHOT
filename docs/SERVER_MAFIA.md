# Серверная Мафия

Контракт отдельного серверного режима от 27 октября 2026 года. В рабочей базе применена миграция `server_mafia_actions` (версия `20261027094910`, исходник `20261027094317_server_mafia_actions.sql`). Edge Function `server-mafia` v1 и `server-wallet` v3 активны с `verify_jwt:true`. Проверены RLS обеих новых таблиц и права RPC: `anon`/`authenticated` не имеют доступа, сервисная роль имеет; функции используют `SECURITY INVOKER`. Проверка advisors не выявила новых замечаний. Исходный клиентский режим, его сохранения и баланс практики продолжают существовать отдельно. Серверный режим не принимает клиентские роли, результаты или суммы в качестве доверенных данных. Интерфейс завершён и прошёл изолированную браузерную приёмку; этот исходный пакет подготовлен для публикации. Настоящая проверка Мафии под аккаунтом владельца на production выполняется отдельно после публикации.

## Правила и порядок игры

За столом один человек и шесть ботов. Сервер случайно распределяет две роли мафии, одного комиссара, одного доктора и трёх мирных жителей. Сложность — `easy`, `normal` или `hard`; она меняет ошибки и глубину публичных наблюдений ботов, а не доступ к чужим секретам.

Город побеждает, когда живых участников мафии не осталось. Мафия побеждает, когда её живых участников не меньше, чем остальных живых игроков. Результат человека определяется победой его команды, даже если он выбыл раньше. После 25 раундов без победителя наступает ничья.

Правила извлекаются генератором `scripts/sync-server-mafia-core.cjs` из `mafiaCore` и начального состояния в `dist/mafia.html`. `supabase/functions/server-mafia/core.mjs` — сгенерированный файл, его нельзя редактировать независимо от канонического движка. Проверка `--check` выявляет расхождение. Серверная обёртка добавляет проверку входных действий, целостности сохранения, допустимости результата и расчёт защищённого баланса. Случайность подаётся явно; сервер использует криптографический источник.

| Фаза | Действие игрока и результат |
| --- | --- |
| `night` | Мафия выбирает цель вне своей команды; комиссар проверяет ещё не проверенного другого живого игрока; доктор защищает любого живого игрока, включая себя. Выбор подтверждается отдельно. Мирный житель или наблюдатель просто завершает ночь. |
| `dawn` | Показан публичный исход ночи. Комиссар отдельно получает собственную проверку. Продолжение открывает обсуждение. |
| `day` | Живые боты высказывают версии с публичными основаниями. Продолжение открывает голосование. Версии не являются доказательствами роли. |
| `vote` | Живой человек выбирает другого живого игрока и подтверждает голос. Выбывший человек запускает голоса ботов без собственного бюллетеня. |
| `voteResult` | Показаны бюллетени и итог. Единственный лидер голосования выбывает; при равенстве лидеров никто не исключается. Продолжение начинает следующую ночь либо завершает 25-й раунд ничьёй. |
| `result` | Партия завершена, роли открыты, результат и расчёт сохранены. Доступна новая партия с новой случайной ролью. |

Если ночь или голосование уже определили победившую команду, движок сразу переходит в `result`. В результате остаются фактический последний исход и история голосования. Добровольная сдача активной партии завершает её без награды; она не является поражением команды по обычным условиям правил.

Выбывший человек может наблюдать по фазам или досмотреть партию одним действием `finish`. Сервер выполняет те же переходы и решения ботов, что при ручном продолжении; новый вход не списывается. Живой игрок не может передать свои действия автоматическому досмотру.

## Скрытая информация

Публичная проекция передаёт собственную роль, роли выбывших игроков и роли живых союзников мафии, если человек сам играет за мафию. Другие живые роли представлены `role:null`. После завершения партии открываются все роли. Число живых участников мафии не публикуется отдельно до результата.

`knowledge` содержит только собственные проверки комиссара: `mafia` или `town`. Ответ «не мафия» не раскрывает точную роль доктора или мирного. `privateNotes` относятся только к человеку. Знания комиссара-бота, выбранная ночная цель мафии и защита доктора не входят в ответ.

Публичные сообщения о погибших, бюллетени и аргументы ботов соответствуют уже открытым событиям. Бот получает только публичную историю, свои разрешённые проверки и союзников собственной мафии. Личные пометки человека — `suspect`, `unsure`, `trust` — не являются проверкой роли и не меняют решения ботов. Они сохраняются вместе с серверной партией.

Подсветка выбранной цели до подтверждения остаётся в интерфейсе. Выбор сам по себе не выполняет проверку комиссара, покушение или голосование. После конфликта версий цель нужно выбрать заново по актуальной партии.

## API

`POST https://cyzbraifdkrqicdsbuwe.supabase.co/functions/v1/server-mafia`

Нужны JSON, публичный `apikey` проекта и `Authorization: Bearer <access_token>` постоянного аккаунта. Edge проверяет пользователя через Auth. Анонимный пользователь не допускается; UID берётся из подтверждённой сессии, а не из тела запроса. Разрешены production-origin Vercel и Sites. Клиент не получает сервисный ключ. Лишние поля и неверные сочетания фазы и действия отклоняются.

| Операция | Тело запроса |
| --- | --- |
| Загрузить партию | `{ "op": "load" }` |
| Новая партия | `{ "op": "start", "actionId": "UUID", "expectedRevision": 0, "difficulty": "normal", "stake": 0 }` |
| Подтвердить ночную цель | `{ "op": "action", "actionId": "UUID", "expectedRevision": 1, "gameId": "TABLE_UUID", "action": { "type": "night", "target": 2 } }` |
| Завершить ночь без собственной цели | Тот же конверт, `action: { "type": "night" }` |
| Проголосовать | Тот же конверт, `action: { "type": "vote", "target": 2 }` |
| Запустить голосование как наблюдатель | Тот же конверт, `action: { "type": "vote" }` |
| Продолжить текущую фазу | Тот же конверт, `action: { "type": "continue" }` |
| Досмотреть после собственного выбытия | Тот же конверт, `action: { "type": "finish" }` |
| Поставить личную пометку | Тот же конверт, `action: { "type": "mark", "target": 2, "mark": "suspect" }` |
| Удалить пометку | Тот же конверт, `action: { "type": "mark", "target": 2, "mark": "" }` |
| Сдаться | Тот же конверт, `action: { "type": "resign" }` |

Места — целые числа 0–6; 0 принадлежит человеку. Самозащита доктора допускает `target:0`; голос против себя запрещён. У ночного действия без доступной цели поле `target` отсутствует. `stake` — 0 или 100, по умолчанию 0. Начало новой партии поверх активной запрещено.

Ответ: `{status:"ok"|"saved"|"conflict",revision,game}`; до первого старта `game:null`. Ревизия монотонна для серверной Мафии аккаунта и сохраняется между партиями. `legal:{actions,targets,marks}` перечисляет доступные действия и места; сервер повторно проверяет их при каждом запросе.

Игра содержит `id`, `version:3`, `difficulty`, `round`, `phase`, `over`, `resigned`, `winningTeam`, `win`, `draw`, `resultReason`, `message`, `nightText`, `players`, `knowledge`, `privateNotes`, `personalMarks`, `votes`, `ballots`, `voteHistory`, `eliminated`, `statements`, `log`, `voteFacts`, `economy` и `legal`. `winningTeam` равен `null`, `town`, `mafia` или `draw`. Итоговый разбор `voteFacts` показывает фактические цели голосов человека после раскрытия ролей; он не приписывает одному голосу причину всего результата.

## Сохранение и экономика

Миграция `20261027094317_server_mafia_actions.sql` создаёт закрытые таблицы `vezdehot_private.server_mafia_games` и `server_mafia_receipts` для состояния и постоянных квитанций. RPC `server_mafia_read` и `server_mafia_commit` доступны только сервисной роли. Браузерные роли не читают закрытую раздачу напрямую. RLS остаётся дополнительным уровнем защиты.

Перед отправкой клиент сохраняет точное тело мутации. При потерянном ответе повторяются прежний `actionId` и прежний запрос. Повтор UUID с другим телом отклоняется. CAS по `expectedRevision` не позволяет двум устройствам записать разные ходы поверх одной версии. После получения старой квитанции клиент читает текущую партию, не заменяя новый ход другого устройства устаревшим ответом.

Бесплатная практика включена по умолчанию и не меняет кошелёк, XP, статистику или ревизию кошелька. Необязательный вход 100 V использует отдельный [серверный баланс](SERVER_ECONOMY.md). Это игровые монеты без денежной стоимости.

| Итог платной партии | Возврат | Изменение с учётом входа | XP |
| --- | ---: | ---: | ---: |
| Победила команда человека | 250 V | +150 V | 130 |
| Победила другая команда | 0 V | −100 V | 25 |
| Ничья после 25 раундов | 100 V | 0 V | 40 |
| Добровольная сдача | 0 V | −100 V | 0 |

Выбытие человека само по себе не рассчитывает результат: команда ещё может победить. Однократные вход и окончательный расчёт записываются атомарно с состоянием и квитанцией. SQL дополнительно проверяет экономику и допустимость итогового состояния. Недостаток средств возвращает `insufficient_funds`, не создавая новую партию и списание. После подтверждения клиент отдельно загружает свежий кошелёк.

## Проверки и ограничения

Команды для этого режима:

```sh
node scripts/sync-server-mafia-core.cjs --check
node --test tests/server-mafia-engine.cjs tests/server-mafia-endpoint.cjs tests/server-mafia-client.cjs tests/server-mafia-ui.cjs
node scripts/test-server-mafia-sql.cjs /absolute/path/to/node_modules/@electric-sql/pglite
node scripts/test-server-mafia-integration.cjs /absolute/path/to/node_modules/@electric-sql/pglite
```

Отдельный прогон движка и Edge: 26 тестов прошли, включая 600 полных партий по ролям/сложностям/ставкам и 80 сравнений полного хода с каноническим ядром. Проверены проекция без лишних вложенных полей, правдоподобная история выбывания и запрет проверок комиссара до завершения соответствующей ночи. Перестановка ключей JSONB не ломает восстановление.

Отдельно прошли 26 тестов клиента и интерфейса: восстановление точного запроса, изоляция аккаунта, конфликт версий, выбор с подтверждением, платный старт и блокировка при нехватке монет, раскрытие информации только по правилам, повторная партия и вывод последней ночи/голосования в финале. Валидатор публичной проекции прошёл 100 полных партий настоящего движка с четырьмя ролями человека и досмотром после выбытия.

Изолированный интеграционный прогон `test-server-mafia-integration.cjs` прошёл: настоящий клиент → Edge → движок → SQL в одноразовом PGlite. Проверены все четыре роли человека, самооборона доктора, союзник мафии, собственные записи комиссара, пометки и восстановление. Потерянные ответы входа, ночи и голосования не повторяют действия; конфликт двух клиентов и другое тело с тем же UUID отклоняются. Досмотр после выбытия сохраняет командные победу и поражение с однократными выплатами 250 V/130 XP или 0 V/25 XP. Сдача не даёт XP; бесплатная партия не меняет кошелёк и его ревизию. Проверки публичных ответов не обнаружили закрытых ролей живых соперников, чужих знаний или ночных целей. Это изолированная проверка без production-данных. Повторный полный прогон `node --test tests/*.cjs`: 574 теста прошли, ошибок и пропусков нет. Интеграционный прогон с настоящим клиентом, Edge, движком и SQL повторно завершился успешно.

На изолированном браузерном стенде с настоящим движком и тестовым transport проверены ширины 320, 390, 844 (горизонтальный экран) и 1440 px. На 390 px подтверждены выбор цели без раннего действия, проверка комиссара, собственный результат проверки, личная пометка «Доверяю» и её восстановление после перезагрузки. На горизонтальном экране шириной 844 px цель и подтверждение находятся рядом; на 1440 px просмотрены итог голосования с тремя голосами и фактические бюллетени. Терминальная вторая ночь показывает победу мафии, поражение стороны человека и последнего погибшего. Повторная партия выдаёт новую роль; в проверенном случае — мирного жителя. На 320 px закреплённое действие остаётся видимым. На всех размерах `scrollWidth` совпадает с `clientWidth`: горизонтального переполнения нет. Исправлены переносы названий фаз и положение личного блокнота. Это браузерная проверка изолированных данных, а не вход на реальном телефоне.

Это одиночная игра против ботов, без комнат с друзьями. Для серверного режима нужна сеть; неопределённый запрос должен получить подтверждение до следующего действия. Реальный Google-вход и продолжение Дурака и Бункера между Vercel и Sites проверены на одном локальном Edge. Эти проверки не подтверждают Мафию, расчёт платной партии или перенос между физическими телефоном и ПК. Реальный touch и телефон → ПК остаются отдельной приёмкой.
